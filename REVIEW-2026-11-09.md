## Tier 1 — HIGH (crashes / hangs, realistic triggers)

### H1. `start_server` deadlocks on the non-reentrant `_server_lock` — 98%
`infra/local_model.py:1022→1036` — `start_server` holds `threading.Lock` and calls
`stop_server()` on the model-switch path, which re-acquires the same lock → the calling
thread hangs forever holding the lock.
- Trigger: switch models (Use + OK) while a healthy server runs a different model, then
  any `ensure_running` (boot worker, Start server button).
- Worse: `closeEvent`'s `stop_server` then also blocks → **the app cannot quit**.
- The suite misses it because `tests/test_local_model.py:370` mocks `stop_server`
  exactly on this path (without the mock the test would *hang*, not fail).
- Fix: `RLock` or an unlocked `_stop_server_locked()` inner helper + regression test
  with the real `stop_server`.

### H2. `_BandwidthLimiter.acquire` hangs forever when limit < chunk size; the fix landed in dead code — 92%
`dlmgr/engine.py:62-74` — allowance is clamped to `_limit` and the loop only exits at
`allowance >= nbytes` (chunk = 65536). Any configured limit below 64 KiB/s (GUI accepts
1–63 KB/s) → every file download freezes on its first chunk. Workers spin inside
`acquire` with no stop check → pause/cancel/engine-stop cannot free them.
- The 2026-11-06 churn fixed this exact bug in `dlmgr/scheduler.py::TokenBucketThrottler`
  — but `TokenBucketThrottler`/`PriorityScheduler` are **dead code** (only importers:
  itself + `tests/test_scheduler.py`). The engine funnels through `_BandwidthLimiter`.
- Fix: port the oversized-grant logic into `_BandwidthLimiter` + oversized regression
  test against it (current test only covers n ≤ limit).

### H3. `probe_gguf` unbounded loop on crafted string-array count — 85%
`infra/local_model.py:479-482` — string-array branch loops `count` times with no cap
(the `> 2**40` guard only covers fixed-size element types); at EOF `read_string` returns
`b""` → never raises → a GGUF declaring 2^62 strings loops effectively forever.
- Runs on the **GUI thread** via `settings_dialog._refresh_local_rows → entry_ctx`, and
  in the chat worker via `context_for_config`. Custom HF models = arbitrary downloaded
  files, so "hostile/corrupt GGUF" is a supported input.
- Fix: cap string-array count (e.g. > 2^24 → reject) + treat short reads as truncation;
  add a crafted-GGUF test.

### H4. `time-pos` observer re-enters libmpv natively — the documented AV class — 90% [PRE-EXISTING]
`iptv/player.py:322-326` — `_pos` reads `self._mpv.duration` (native `mpv_get_property`)
inside the property observer, on mpv's event thread, firing every position tick. The
churn fixed the sibling (`_cache_stall` → `_paused_state`) but not this one; the
out-of-process backend already models the correct pattern (observe `duration` into a
Python attr). This is exactly the crash family AGENTS.md bans ("observers must NEVER
re-enter libmpv natively from inside a callback").
- Fix: register a `duration` observer mirroring into `self._duration_state`; `_pos`
  reads the attr. Add the no-native-reentry test for `_pos` (none exists).

## Tier 2 — MED

### M1. ReDoS in `_STREAM_URL_RE` freezes the whole app (GIL held) — 80%
`dlmgr/extractors/page_scan.py:102-105` — lazy `+?` + alternation = O(L²) on a 5 MiB
hostile page (≈1.25e13 sre ops in one C-level match; no GIL release, Ctrl+C dead).
Site Grabber's core use case is arbitrary video sites. Fix: bound the token
(`{1,2048}?`) or locate the extension literal first and walk back to the scheme.

### M2. Sources dialog OK silently wipes `origin`, `torznab_caps`, `popularity`, `categories` — 85%
`gui/sources_dialog.py:259-281` rebuilds each row as a 5-field `SourceConfig` while the
churn made `origin`/`torznab_caps` load-bearing. Chain: manual sources become `""` →
Jackett-queried + suspect-probed → 3 bogus "Unknown indexer" strikes → permanently
zombie-skipped; jackett-origin wipe disables zombie auto-removal forever; worst case a
manually re-added genuine Jackett id gets **deleted** by a later sync. Fix: carry over
fields by id; new rows get `origin="manual"`. Zero test coverage today.

### M3. IPTV remote-body downloads are unbounded (OOM/disk DoS on advertised flows) — 70-75%
- `iptv/manager.py:390` `_download_m3u` — `requests.get(..., stream=False)`, no cap;
  runs for every enabled source at startup.
- `iptv/epg.py:196-222` — streams to temp file with **no byte cap**, then gzip
  `src.read()` fully into RAM (bomb → tens of GB); unbounded `<programme>` list.
- `iptv/xtream.py:133` — same uncapped `requests.get` + `.json()`.
All contradict the durable rule "never buffer an unbounded remote body into the GUI
process" (enforced on agent paths since 2026-09-15, never applied here). Fix: streamed
caps mirroring `read_capped`.

### M4. Commander batch-rename: bad regex replace crashes the preview on every keystroke — 92%
`gui/commander_rename.py:118` — `re.error` from the *replacement template*
(`\p`, trailing `\`, `N\A`…) escapes the `(ValueError, IndexError)` guard at :129 →
uncaught exception in the `textChanged` slot, frozen preview. The invalid-*Find* path
is handled; only Replace is missed. Fix: add `re.error` to the catch; focused test.

### M5. Commander `_close_tab` leaves `_active` pointing at a destroyed FilePane — 70%
`gui/commander_tab.py:1203-1226` — no re-anchor after `deleteLater()`; programmatic
closes (Ctrl+W, close-X without focus change) can leave every commander shortcut
raising `RuntimeError: Internal C++ object already deleted`. Fix: re-anchor
`_set_active(tabs.currentWidget())` in `_close_tab`; test flushes `deleteLater` then
drives a shortcut.

### M6. Linux Jackett bootstrap: unpinned "latest" download, unsanitized tar extract, executed — 85%
`infra/jackett_setup.py:246-348` — `releases/latest` → first matching asset → streamed
(size cap only) → `tarfile.extractall` (py3.11: no `..`/absolute filtering) →
`Popen([binary])`. Regresses the discipline everywhere else (FlareSolverr digest vs
PINNED.json, Windows Jackett bundle digest-pinned at build). Zero test coverage for the
Linux path. Fix: pin version + verify asset digest + filter members.

### M7. Model switch while old model is still LOADING → wrong model serves, state file lies — 70%
`infra/local_model.py:1024-1044` — stop only runs when `is_running()` (health 200);
mid-load (503) → B spawns next to loading A; loser dies on bind; state file says B
while A serves, and `ensure_running` never corrects. Fix after H1: stop a
mid-load-budget pid whose model differs.

### M8. `test_oh_room` writes the user's real `~/.deeptorrent/room-portal` profile — 75%
`tests/test_oh_room.py:547-554` delenvs `DF_NO_ROOM` and constructs a real `RoomTab`
whose profile path is hardcoded (`gui/room_tab.py:127-128`) — touches the same
leveldb/cookie store as the installed app. Exactly the test-hygiene class the repo
bans (cf. wiped-config incident). Fix: env-overridable storage root (mirror
`DF_MODELS_DIR`) or monkeypatch `Path.home` in the test.

### M9. Taskbar progress feature is silently dead on Windows — 92%
`gui/win_taskbar.py:59-67` — `ctypes.byref(uuid.UUID)` raises `TypeError` (swallowed
by the blanket except) so COM is never reached; even fixed, vtable slots are wrong
(`11/12` = RegisterTab/UnregisterTab; correct = **9/10** SetProgressValue/State); COM
object never Released. Feeds from `_update_status_bar` every second for nothing.
Offscreen test passes because `hwnd=0` early-returns. Fix: `_GUID` struct from
`UUID.bytes_le`, slots 9/10, Release; source-pin test for the constants.

### M10. `dht_nodes` always 0 in `_get_session_stats`; fallback unreachable — 85%
`engine/torrent_engine.py:697-707` — `session.session_stats_metrics()` doesn't exist
as a session method (module-level API) → `AttributeError` swallowed → always 0.
Latent (no production caller) but the churn broke it and no test notices.

### M11. `http_client.read_capped` defects — 75-80%
`dlmgr/http_client.py:171-208` — (a) oversized-body early return **leaks the response**
(the `finally: close` is attached only to the second try); (b) mid-stream network
errors are swallowed and the truncated body is returned as if complete (grabber/
extractor then parse a half page). Fix: single try/finally; only fall back to buffered
content when zero chunks arrived.
